# SCNU PICK PC 구현 명세 — v2

기준 파일: [notice-prototype.html](notice-prototype.html) · 갱신: 2026-09-21

**로그인부터 최초 등록, 추천·신규·상세·캘린더·정보 수정까지 요청한 전체 PC 디자인 흐름을 구현했습니다.** 실제 서비스의 인증·메일·데이터 수집·추천 API는 포함하지 않습니다. React 구현 시 이 코드의 화면·상태·효과를 참조합니다. 제품 기획의 기준은 [product-scope.md](../../product-scope.md)입니다.

## 1. 실행과 시연

HTML 한 파일을 내려받아 브라우저에서 엽니다. 별도 설치나 외부 CDN 요청이 없습니다. GitHub의 파일 보기 화면에서는 실행되지 않습니다. 로컬 서버로 확인하려면 저장소 루트에서 다음을 실행합니다.

```sh
python -m http.server 8000
```

브라우저에서 `http://localhost:8000/docs/design/pc/notice-prototype.html`을 엽니다.

- 신규 가입: `new@example.com` 같은 예시 이메일 + 임의의 8~128자 비밀번호. 실제 비밀번호를 입력하지 않습니다.
- 기존 사용자: `demo@example.com` + 임의의 8~128자 비밀번호 또는 ‘시연 도구 → 기존 사용자 로그인 예시’.
- 로그인 검증은 **이메일 형식·예시 계정 존재 여부·비밀번호 길이만 검사**합니다. 비밀번호 일치 검증, 암호 저장, 실제 로그인은 하지 않습니다.
- 메일 확인: 가입 후 ‘시연 도구 → 메일 확인 성공 시연’. 실제 발송/토큰 처리가 아닙니다.
- 실패: ‘다음 요청 네트워크 실패’를 켠 후 가입·로그인·메일 요청·등록·저장·찜·목록 재시도를 수행합니다. 한 번 실패하면 옵션은 해제됩니다. 모달 저장 실패는 모달을 열기 전에 켭니다.
- 인증 실패: ‘다음 로그인 인증 오류’. 메일 만료와 비밀번호 재설정 링크도 시연 도구에서 재현합니다.
- 모든 요청은 약 500ms 지연으로 로딩·중복 클릭 차단을 보여줍니다.
- 예시 계정·학적·선택값·찜은 현재 탭의 `sessionStorage`에 저장합니다. 비밀번호·인증 토큰은 저장하지 않습니다. 탭 종료 시 보존을 보장하지 않으며 저장이 차단되면 새로고침 시 데이터가 사라질 수 있습니다.
- ‘시연 데이터 초기화’는 이 프로토타입 키만 초기화합니다. 다른 사이트 저장값을 삭제하지 않습니다.
- 시연 도구, 가상 데이터 안내, 고정 기준일은 실제 제품 UI에 포함하지 않습니다.

## 3. 화면 이동과 기존 사용자 분기

| 화면 해시 | 진입/완료 동작 |
| --- | --- |

| `#/signup` | 이메일·비밀번호·확인 입력 → 가입 요청 → 메일 확인 |
| `#/verify` | 확인 대기·다시 확인·재전송·만료. 성공 → 최초 학적 등록 |
| `#/forgot` | 이메일 입력 → 복구 링크 요청 |
| `#/reset-sent` | 계정 존재 여부와 무관한 동일 안내 |
| `#/reset-password` | 유효 링크 → 새 비밀번호, 없거나 만료/사용한 링크 → 새 링크 요청 |

| `#/academic` | 최초 학과·학년·학적 상태 → 관심사 선택 |

| `#/new` | 신규 공지 |

- 로그인되지 않은 사용자가 보호 화면 주소로 접근하면 로그인으로 이동합니다.
- 메일 미확인 계정은 로그인 후 확인 대기로 이동하며 최초 등록·메인에 진입하지 못합니다.
- 메일 확인 후 학적 미등록 → 학적, 학적 초안 저장 완료 → 관심사 선택, 최초 등록 완료 → 추천 메인.
- 기존 사용자는 최초 등록을 반복하지 않습니다. 직접 최초 등록 주소로 접근해도 추천으로 이동합니다.
- 새로고침 시 해당 탭에 저장한 등록 단계와 찜을 복구합니다. 학적은 ‘다음’ 성공 시 초안 저장, 관심사 선택은 선택 즉시 초안 저장합니다. 아직 제출하지 않은 학적 입력값은 새로고침 시 복원하지 않습니다.
- 로그아웃은 로그인 상태를 해제합니다. 프로토타입의 예시 계정별 데이터는 탭 안에 남으므로 재로그인하면 유지됩니다. 실제 서버 데이터 수명과는 별개입니다.
- 요청 중에는 화면 전환/중복 요청을 막습니다. 실제 구현에서 브라우저 이동을 허용할 경우 취소 처리 또는 오래된 응답 무시 처리가 필요합니다.

## 5. 로그인

- 이메일·비밀번호 라벨은 입력과 연결합니다. Enter로 제출할 수 있습니다.
- 이메일 빈 값·형식 오류는 해당 필드 아래 안내합니다. 일반 이메일 도메인을 제한하지 않습니다.
- 비밀번호 ‘보기/숨기기’는 해당 필드만 토글하고 입력값은 유지합니다.
- 제출 시 ‘처리 중…’, 입력/버튼 잠금, `aria-busy` 적용.
- 인증 실패: “이메일 또는 비밀번호를 확인해 주세요.” 전체 오류 안내. 어느 값이 틀렸는지 구분하지 않습니다.
- 네트워크 실패: 입력 유지 및 같은 버튼으로 재시도.
- 회원가입 → 가입 화면, 비밀번호 찾기 → 복구 화면.

## 6. 회원가입과 이메일 확인

### 회원가입

- 이메일 / 비밀번호 / 비밀번호 확인.
- 이메일 형식, 비밀번호 길이, 확인값 일치 검사. 오류 시 첫 오류 필드로 포커스 이동.
- 가입할 수 없는 예시 계정은 로그인·재설정 안내. 실제 계정 중복 공개 여부와 응답 정책은 백엔드와 합의합니다.
- 가입 성공 → 확인 대기. 입력한 이메일을 표시하고 확인 전에는 최초 등록으로 넘어가지 않습니다.
- 가입 화면에서 일반 이메일 허용·학생 인증 없음·메일 소유 확인 목적을 명시합니다.

### 확인 대기 / 만료 / 재전송

- ‘메일 확인 상태 확인’: 서버 확인 여부를 다시 조회하는 동작. 미확인이면 화면 유지 + 안내.
- ‘확인 메일 다시 보내기’: 30초 시연 카운트다운, 대기 중 비활성화. 성공하면 대기 메시지, 실패하면 오류 + 재시도 가능.
- 만료 링크: 오류 안내, 재전송 유도. 만료된 링크로 등록 완료 처리하지 않습니다.
- ‘다른 이메일로 가입’: 가입 화면으로 이동. 실제 서비스에서는 이전 미확인 계정의 정리 정책을 별도로 정합니다.
- 실제 구현: 메일 링크의 서버 토큰 확인 후 인증 상태/사용자 정보 조회. 외부 탭에서 확인 후 돌아온 경우 focus 이벤트 재조회 또는 ‘상태 확인’ 버튼 사용. 토큰은 서버에서 만료·사용 여부 검증.
- 시연: 외부 메일 대신 상단 시연 도구가 확인 성공/만료 이벤트를 만듭니다.

## 7. 비밀번호 재설정

1. 이메일 제출 → “입력한 이메일로 등록된 계정이 있다면 안내를 보내드려요.” 계정 존재 여부와 관계없이 같은 화면.
2. 유효 링크 → 새 비밀번호·확인 입력.
3. 길이/일치 검사 → 변경 요청 → 완료 → 로그인.
4. 만료·사용된 링크 또는 새로고침으로 시연 링크 상태가 사라진 경우 → 사용 불가 안내 → 새 링크 요청.

- 요청·변경 실패 시 입력을 유지하고 재시도를 허용합니다.
- 재설정 토큰은 실제 서비스에서 서버가 검증하고 1회 사용 후 폐기합니다. 프로토타입의 메모리 플래그는 보안 구현이 아닙니다.
- 시연에서는 실제 계정 암호가 변경되지 않습니다. 서버 구현 시 새 암호 적용 및 기존 세션 만료 정책을 합의합니다.

## 8. 최초 학적 등록

- 3단계 표시: 학적 정보 → 관심사 선택 → 등록 완료.
- 학과: 직접 입력, trim, 1~60자. 학과 마스터 데이터 확정 시 검색 선택/ID 방식으로 교체합니다.
- 학년: 기본 미선택, 1~4학년/5학년 이상 시연 선택지.
- 학적 상태: 기본 미선택, 재학/휴학/기타.
- ‘다음’: 필수값 검사 → 초안 저장 → 관심사 선택.
- 저장 실패 시 현재 입력 유지. 최초 등록 완료 플래그는 아직 설정하지 않습니다.
- 뒤 단계에서 ‘이전’으로 돌아오면 성공적으로 저장한 학적 초안을 채웁니다.

## 9. 최초 관심 분야·활동 유형 선택 / 완료

- 두 그룹을 분리하며 각각 최소 1개 필수. 여러 개 선택 가능, 시연에서는 최대 개수 제한 없음.
- 처음에는 선택 없음 안내 + 0개 선택. 선택하면 파란 배경/테두리와 선택 개수 변경.
- 선택된 버튼을 다시 누르면 해제. `aria-pressed`와 상태를 함께 변경합니다.
- 한 그룹이 비어 있으면 그룹 하단 오류와 첫 선택 버튼으로 포커스 이동.
- ‘이전’: 학적 등록으로 복귀, 선택 초안 유지.
- ‘선택 완료’: 요청 중 잠금. 성공한 시점에만 학적과 관심사 저장·등록 완료 상태 설정.
- 실패 시 선택 유지, 기존 완료 정보 변경 없음. 재시도 가능.
- 완료 화면에 학적·관심 분야·활동 유형 요약. ‘추천 공지 보러 가기’로 메인 이동.

## 10. 추천·신규·검색·필터

### 추천

- 신청 마감 지난 공지는 제외합니다. 날짜 없는 공지는 마감을 추정하지 않습니다.
- 학적·관심 분야·활동 유형만 비교합니다. 최신성·마감 임박은 점수에 넣지 않습니다.
- 시연 카드는 ‘조건 일치 N/3’와 실제 선택값 기반 일치 이유를 표시합니다. 실서비스 적합도와 점수는 API 결과로 교체합니다.
- 공지 카드: 제목·출처·추천 근거·D-Day·3줄 요약(대상/활동/일정).
- 관심사 변경과 좌측 내 정보 수정은 같은 수정 모달로 연결합니다.

### 신규

- 원문 등록일 기준 최신순. 마감된 공지도 보여주되 ‘신청 마감’으로 표시합니다.
- 제목·출처·활동·관심 분야 키워드 검색과 출처 필터.

### 필터

- 카테고리는 전체/장학·지원/대외활동/교육·특강 중 단일 선택.
- 마감 임박은 별도 토글, 카테고리·검색·출처 조건과 AND 조합.
- 카테고리 전체는 카테고리 조건만 해제. 초기화는 검색·출처·마감 임박까지 모두 해제합니다.
- 입력 즉시 로컬 필터링. 실제 API 연결 시 250~400ms 디바운스와 이전 응답 무시를 적용합니다.
- 검색 결과 없음 → 빈 안내 + 필터 초기화.
- 목록 상태 시연에서 로딩/빈/오류/정상 확인. 오류는 재시도 가능.

## 11. 상세와 찜

- 카드 빈 영역 클릭 또는 제목 버튼 Enter/Space → 해당 공지 상세 모달.
- 찜 클릭은 상세 열림을 일으키지 않습니다.
- 상세는 공지별 제목·출처·대상·신청/행사 시작·종료·활동·혜택·추천 기준과의 관계를 표시합니다.
- 없는 날짜는 각 항목에 ‘일정 미정’. 마일리지 제도/점수/조건을 분리하고 합산하지 않습니다. 상금 있음/없음/미기재를 구별합니다.
- 가상 공지의 원문 URL은 null입니다. ‘원문 보기’는 URL 없음 안내만 표시하며 무관한 실제 공지를 연결하지 않습니다.
- 실제 원문 URL은 API 검증 후 새 탭으로 열고 `rel="noopener noreferrer"`를 적용합니다. 신청·자격 확인은 운영기관 절차를 따릅니다.
- 찜은 요청 성공 후 상태를 변경하는 방식입니다. 요청 중 버튼 잠금, 실패 시 기존 상태 유지. 낙관적 처리로 바꾸면 실패 rollback 필수.
- 목록과 상세의 같은 공지 찜 표시를 동기화합니다. 추가/해제 시 캘린더도 즉시 갱신합니다.
- 찜은 관심 표시입니다. 신청 완료 상태를 따로 관리하지 않습니다.

## 12. 월간 캘린더

- 찜한 공지만 표시. 신청 시작/마감은 파란 계열, 행사 시작/종료는 초록 계열 + 텍스트 라벨.
- 행사 시작과 종료가 같으면 행사 하나, 다른 날짜면 각각 시작/종료 마커를 표시합니다. 기간 중간 날짜에 별도 막대를 그리지 않습니다.
- 이전/다음 월 이동, 12월↔1월 연도 경계 처리.
- 일정 클릭 → 정확히 해당 공지 상세. 상세에서 찜 해제 시 달력에서도 제거.
- 날짜가 전혀 없는 찜 공지만 우측 ‘일정 미정’ 목록에 표시. 일부 날짜만 있는 공지는 알려진 마커를 표시하고 나머지는 상세에서 일정 미정으로 안내.
- 찜 0개 → 찜 사용 안내. 이번 달 마커 0개 → 다른 달·일정 미정 확인 안내.
- 신청 마감 후 추천에서 빠지더라도 기존 찜·행사 일정 유지.

## 13. 내 정보 수정

- 모달 열 때 저장값을 복사해 별도 초안으로 편집합니다. 최초 등록과 동일한 학적/선택 컴포넌트·검사 사용.
- 저장 성공 시 저장값 교체 → 추천 일치 수·이유·순서 갱신 → 모달 닫기 → 토스트.
- 저장 실패 시 모달/입력/선택 유지, 저장된 기존 정보 유지, 오류 안내 후 재시도.
- 취소/닫기/Esc는 수정 초안 폐기. 다시 열면 이전 저장값.
- 성공/취소/실패 어느 경우에도 기존 찜은 수정하지 않습니다. 캘린더는 같은 찜 ID와 원문 일정에서 계산합니다.
- 배경 클릭으로는 닫지 않습니다. 실수로 입력을 잃지 않도록 명시적 닫기/취소/Esc를 사용합니다.

## 14. 효과·접근성

| 요소 | 효과/상태 |
| --- | --- |
| 카드 hover | Y -2px, 그림자 강화, 180ms |
| 버튼/필터 | 배경·테두리·그림자 150ms, 선택은 배경+텍스트+aria-pressed |
| 화면/모달 | opacity 0→1 + Y 6px→0, 180ms |
| 처리 중 | 버튼 ‘처리 중…’, scope 잠금, aria-busy |
| 목록 로딩 | 회전 표시 800ms, 텍스트 함께 표시 |
| 입력 오류 | 붉은 테두리+필드별 설명, aria-invalid/aria-describedby |
| 포커스 | 3px `#6689ff` outline, offset 4px |
| 모달 | 열 때 내부 첫 버튼으로, Tab/Shift+Tab 내부 순환, Esc 닫기, 닫으면 트리거 복귀 |
| 배경 | 모달 동안 본문/시연 도구 inert, 스크롤 잠금 |
| 모션 줄이기 | prefers-reduced-motion: reduce에서 애니메이션/전환/hover 이동 제거 |

- 페이지 전환 후 제목에 프로그램 방식으로 포커스 이동. 제목은 일반 Tab 순서에서 제외합니다.
- 라벨 연결, 키보드 버튼 동작, 오류 role=alert, 토스트/목록 상태 aria-live 안내.
- 화면 크기가 작아져도 모달 내부 스크롤로 마지막 저장/취소 버튼에 접근할 수 있습니다.

## 15. API 연결 기준

경로·필드·오류 코드는 [API 합의 문서](../../api-contract.md)에서 결정합니다. 다음은 필요한 상태의 의미이며 확정 API 계약이 아닙니다.

| 데이터/동작 | 프론트가 필요한 결과 |
| --- | --- |
| 로그인·사용자 조회 | 인증 사용자, emailVerified, onboardingCompleted, profile |
| 가입/메일 확인/재발송 | 성공 여부, 미확인/만료/속도 제한, 재요청 가능 시각 |
| 비밀번호 복구 | 계정 존재 여부 비노출 요청 응답, 토큰 검증·사용 완료 |
| 최초 등록 | 학적·관심 분야 ID·활동 유형 ID, 전체 저장 성공 시 완료 플래그 |
| 정보 수정 | 성공한 최종 프로필, 추천 캐시 무효화/다시 조회 |
| 찜 | 공지 ID 기준 사용자별 추가/삭제, 중복 요청 방지 |
| 공지/일정 | 공지 ID, 출처, 원문 URL, 등록일, 명시된 날짜, 혜택별 정보 |

- 브라우저의 해시/완료 플래그로 접근 권한을 신뢰하지 않습니다. 서버에서 인증·이메일 확인·소유권을 검증합니다.
- 실제 비밀번호는 서버의 안전한 인증 구현으로 전달하며 브라우저 저장소에 보관하지 않습니다. 인증 방식/CSRF/세션 만료는 백엔드와 합의합니다.
- 재발송/복구 요청은 서버에서 횟수·시간 제한 및 토큰 만료/1회 사용을 강제합니다.
- 최초 등록 전체 저장을 원자적으로 완료하거나 명시적인 단계별 저장 API를 둡니다. 중간 실패를 완료 처리하지 않습니다.
- 프로필 갱신은 찜 API를 호출하거나 찜을 초기화하지 않습니다.
- 날짜가 date-only인지 타임스탬프인지, 시간대, 당일 마감 시각, 마감 미정 처리 등을 합의합니다. 시연의 고정 날짜 문자열 비교를 그대로 운영에 쓰지 않습니다.
- 네트워크 실패·401 세션 만료·검증 오류·429 요청 제한 응답을 분리하고, 서버 오류를 화면의 일반 안내로 변환합니다.
- 서버에서 온 제목/이메일/텍스트는 React의 기본 escaping을 사용합니다. 신뢰할 수 없는 HTML을 그대로 삽입하지 않습니다.

## 16. 검증과 인수 기준

브라우저 흐름 검증: [tests/prototype-flow.cjs](tests/prototype-flow.cjs).

Playwright가 설치된 환경에서:

```sh
node docs/design/pc/tests/prototype-flow.cjs
```

테스트 환경에 Playwright가 없다면 별도 테스트 폴더에 설치 후 `SCNU_PLAYWRIGHT_MODULE`로 패키지 절대 경로를 지정합니다. `SCNU_CHROMIUM_PATH`는 별도 Chromium 실행 파일, `SCNU_SCREENSHOT_DIR`은 화면 캡처 출력 위치를 지정하는 선택 환경변수입니다. `SCNU_CHROMIUM_ARGS_MODULE`은 `.default.args`를 제공하는 Chromium 런처 모듈을 사용해야 하는 특수 환경의 선택값입니다.

실행 결과 (2026-09-21): Chromium에서 **23개 시나리오 통과, pageerror 0건**. 로그인·가입·학적·관심사·완료·재설정 화면 PNG를 시각 검수했고 1440×1000 및 모달 1440×900/1280×800 환경을 확인했습니다. 실제 서비스 테스트 결과가 아닙니다.

검증 범위:

- 비로그인 보호 화면 접근, 가입 오류/실패/재시도, 확인 대기/만료/재전송
- 최초 학적 필수값, 새로고침·이전 단계 초안 보존, 두 선택 그룹 유효성 검사
- 등록 완료/기존 사용자 분기, 실패 시 미완료 상태 유지
- 찜 실패·성공·캘린더 연동, 상세 모달 키보드/포커스
- 내 정보 취소·실패·성공 및 추천 갱신/찜 유지
- 검색/출처/빈 결과, 날짜 미정·마감 지난 행사 유지, 연도 경계
- 복구 요청 실패·만료·새 링크·비밀번호 변경 완료 흐름
- 1440px/1280px 가로 넘침 및 수정 모달 크기, 브라우저 오류, 암호 미저장

이는 가상 데이터 UI 검증입니다. 실제 계정·메일·비밀번호·권한·추천 품질·수집 데이터 검증은 API 연결 후 별도로 진행해야 합니다.
