# SCNU PICK PC 구현 명세 — v3

갱신: 2026-09-21

최신 계정 정책과 화면 동작은 `frontend/src`의 React 구현과 [제품 범위](../../product-scope.md)를 기준으로 합니다. [기존 단일 HTML 프로토타입](notice-prototype.html), 해당 자동화 스크립트와 PNG는 현재 계정 정책을 반영하지 않는 시각 참고용 레거시 자료입니다.

## 1. 실행과 시연

```sh
cd frontend
npm install
npm run dev
```

- 기존 사용자: 아이디 `demo`와 임의의 8~128자 비밀번호를 사용합니다.
- 신규 사용자는 영문 소문자와 숫자 조합 4~20자 아이디로 가입합니다.
- 대문자로 입력한 아이디는 즉시 소문자로 변환합니다.
- 로그인 검증은 예시 계정 존재 여부와 비밀번호 길이만 검사합니다. 비밀번호 일치 검증이나 암호 저장은 하지 않습니다.
- 계정과 로그인 상태는 현재 탭의 `sessionStorage`, 아이디별 프로필과 찜은 `localStorage`에 저장합니다.
- 실제 인증·데이터 수집·추천 API는 포함하지 않습니다.

| 구분 | 기준 |

| 계정 | 아이디 + 비밀번호 |
| 아이디 | 영문 소문자·숫자 4~20자, 대소문자 미구분 |

| 마감 | 필터와 D-Day 배지, 신청 마감 공지는 추천 후보 제외 |

| 선택 목록 | 관심: AI/개발/창업/취업/장학, 활동: 프로젝트/특강/공모전/멘토링 |

## 3. 화면 이동과 접근 제어

| 경로 | 진입/완료 동작 |
| --- | --- |
| `/login` | 로그인 성공 후 사용자 등록 상태에 따라 분기 |
| `/signup` | 아이디·비밀번호·확인 입력 후 최초 학적 등록으로 이동 |
| `/academic` | 학과·학년·학적 상태 저장 후 관심사 선택으로 이동 |
| `/preferences` | 관심 분야와 활동 유형 저장 후 등록 완료로 이동 |
| `/complete` | 등록 결과 요약 후 추천 메인으로 이동 |
| `/recommend` | 등록 완료 사용자의 기본 메인 |
| `/new` | 신규 공지 |
| `/calendar` | 찜과 연동한 월간 일정 |

- 미로그인 사용자가 보호 화면에 접근하면 `/login`으로 이동합니다.
- 학적 초안이 없는 미완료 사용자는 `/academic`, 초안이 있는 사용자는 `/preferences`로 이동합니다.
- 등록 완료 사용자는 최초 등록 화면에 직접 접근해도 `/recommend`로 이동합니다.
- 존재하지 않는 경로는 `/recommend`를 거쳐 사용자 상태에 맞는 화면으로 이동합니다.
- 로그아웃은 로그인 상태만 해제하며 해당 아이디의 프로필과 찜은 유지합니다.

## 5. 로그인과 회원가입

### 로그인

- 아이디·비밀번호 라벨을 입력과 연결하고 Enter 제출을 지원합니다.
- 아이디는 입력 즉시 소문자로 변환하며 영문 소문자·숫자 4~20자를 검사합니다.
- 비밀번호 보기/숨기기는 입력값을 유지한 채 해당 필드만 전환합니다.
- 인증 실패는 “아이디 또는 비밀번호를 확인해 주세요.”로 통일합니다.
- 제출 중에는 입력과 버튼을 잠그고 `aria-busy`를 적용합니다.
- 완료 사용자는 추천 메인, 미완료 사용자는 저장된 등록 단계로 이동합니다.

### 회원가입

- 아이디 / 비밀번호 / 비밀번호 확인을 입력합니다.
- 아이디 형식, 비밀번호 8~128자, 확인값 일치를 검사합니다.
- 중복 아이디는 “이미 사용 중인 아이디입니다.”로 안내합니다.
- 가입 성공 시 로그인 상태를 만들고 `/academic`으로 바로 이동합니다.
- 실제 서버 연동 시 아이디 중복과 유효성은 서버에서도 동일하게 검증합니다.

## 6. 최초 등록

- 3단계는 학적 정보 → 관심사 선택 → 등록 완료입니다.
- 학과는 trim 후 1~60자, 학년은 1~4학년/5학년 이상, 학적 상태는 재학/휴학/기타입니다.
- 학적 저장 성공 후에만 관심사 단계로 이동하며 실패 시 입력을 유지합니다.
- 관심 분야와 활동 유형은 그룹별 최소 1개를 선택하고 복수 선택할 수 있습니다.
- 선택 초안은 즉시 저장하고 이전 단계로 돌아와도 유지합니다.
- 최종 저장 성공 시에만 `onboardingCompleted`를 설정합니다.
- 완료 화면에는 학적·관심 분야·활동 유형 요약을 표시합니다.

## 7. 추천·신규·상세

- 추천은 학적·관심 분야·활동 유형의 조건 일치 수 0~3을 기준으로 정렬합니다.
- 최신성이나 마감 임박 여부를 추천 점수에 사용하지 않습니다.
- 추천 카드는 조건 일치 수, 실제 일치 이유, 대상·활동·일정을 표시합니다.
- 신규 공지는 원문 등록일 기준 최신순이며 검색·출처·카테고리·마감 임박 필터를 제공합니다.
- 상세는 대상, 신청/행사 일정, 혜택, 추천 관계와 찜 상태를 표시합니다.
- 원문에 없는 날짜와 혜택은 추정하지 않고 일정 미정 또는 미기재로 표시합니다.

## 8. 찜과 캘린더

- 찜은 현재 아이디에 귀속하며 다른 아이디의 데이터와 분리합니다.
- 찜 요청 중 중복 입력을 막고 실패 시 기존 상태를 유지합니다.
- 신청 시작·마감은 파란 계열, 행사 시작·종료는 초록 계열로 구분합니다.
- 행사 시작일과 종료일이 같으면 하나의 행사 마커만 표시합니다.
- 날짜가 전혀 없는 찜 공지는 일정 미정 목록에 표시합니다.
- 프로필 변경이나 신청 마감 이후에도 기존 찜과 예정된 행사 일정은 유지합니다.

## 9. 내 정보 수정

- 모달을 열 때 저장된 프로필을 복사해 별도 초안으로 편집합니다.
- 최초 등록과 같은 학적·관심사·활동 유형 검증을 적용합니다.
- 저장 성공 시 추천 조건과 이유를 다시 계산하고 모달을 닫습니다.
- 저장 실패, 취소, 닫기, Esc에서는 저장된 프로필과 찜을 변경하지 않습니다.

## 10. 접근성과 상태

- 입력 오류는 `aria-invalid`, 연결된 설명과 `role="alert"`를 사용합니다.
- 선택 버튼은 `aria-pressed`, 처리 중 영역은 `aria-busy`를 사용합니다.
- 모달은 포커스 순환, Esc 닫기, 닫은 뒤 트리거 포커스 복귀를 지원합니다.
- 목록은 로딩·빈 결과·오류·정상 상태를 구분하고 오류 상태에서 재시도할 수 있습니다.
- `prefers-reduced-motion: reduce`에서는 애니메이션과 이동 효과를 줄입니다.

## 11. API 연결 기준

| 데이터/동작 | 프론트가 필요한 결과 |
| --- | --- |
| 가입·로그인·사용자 조회 | username, onboardingCompleted, profile |
| 최초 등록 | 학적·관심 분야 ID·활동 유형 ID, 전체 저장 성공 여부 |
| 정보 수정 | 성공한 최종 프로필과 추천 캐시 갱신 |
| 찜 | 공지 ID 기준 사용자별 추가·삭제 결과 |
| 공지/일정 | 공지 ID, 출처, 원문 URL, 등록일, 명시된 날짜와 혜택 |

- 서버는 아이디 형식·중복, 인증, 소유권을 다시 검증합니다.
- 비밀번호는 브라우저 저장소에 보관하지 않으며 인증 방식, CSRF, 세션 만료는 백엔드와 합의합니다.
- 최초 등록은 전체 저장을 원자적으로 완료하거나 명시적인 단계별 저장 API를 사용합니다.
- 프로필 갱신은 찜을 초기화하지 않습니다.
- 네트워크 실패, 401, 검증 오류, 429와 서버 오류를 구분해 처리합니다.

## 12. 검증과 인수 기준

React 검증 명령:

```sh
cd frontend
npm run lint
npm run typecheck
npm run test:run
npm run build
```

필수 검증 범위:

- 아이디 형식·소문자 정규화·중복, 비밀번호 길이·확인값
- 미로그인 보호 화면 접근과 완료/미완료 사용자 분기
- 가입 직후 학적 등록 진입과 등록 단계 초안 보존
- 프로필 변경 후 추천 갱신과 찜 유지
- 아이디별 찜·프로필 분리와 캘린더 연동
- 검색·필터·빈 결과·오류·상세 모달 접근성

레거시 PC 프로토타입의 테스트 결과는 현재 React 계정 흐름의 인수 기준으로 사용하지 않습니다.
