# SCNU PICK PC 구현 명세

이 문서는 `docs/design/pc/notice-prototype.html`을 기준으로 프론트엔드 담당자가 React 화면을 구현할 때 필요한 화면 동작과 상태를 정리한 전달 문서입니다.

## 1. 범위

PC 우선 화면이며 핵심 메뉴는 **추천 공지 / 신규 공지 / 내 캘린더**입니다. 내 정보 수정은 상단 진입점과 추천 화면의 관심사 변경 버튼에서 동일한 수정 화면으로 연결합니다.

수집 출처는 다음 세 곳만 사용합니다.

- 순천대학교 대표 공지
- SW중심대학사업단
- AI인재양성부트캠프사업단

글로컬사업단은 현재 범위에서 제외합니다.

## 2. 공통 레이아웃

- 좌측 고정형 사이드바: 서비스명, 3개 메뉴, 내 정보 수정.
- 본문은 넓은 PC 화면을 기준으로 중앙 정렬하고 카드 폭을 충분히 확보합니다.
- 카드와 패널은 밝은 배경, 얕은 테두리, 둥근 모서리, 약한 그림자를 사용합니다.
- 모바일 대응은 필수 구현 범위가 아니지만 960px 이하에서는 단일 컬럼으로 무너지도록 구성할 수 있습니다.
- 키보드 포커스가 가능한 요소는 버튼/링크/입력으로 구현하고 클릭 가능한 카드 내부에 별도 버튼이 있을 경우 이벤트 중첩을 방지합니다.

## 3. 추천 공지

### 기본

- 서비스 진입 후 첫 메인 화면입니다.
- 카드에는 제목, 출처, 추천도, 추천 이유, D-Day, 3줄 요약을 표시합니다.
- 3줄 요약 항목은 **대상 / 활동 / 신청·행사 일정**입니다.
- 최신성이나 마감 임박 여부를 추천 점수에 가산하지 않습니다.
- 신청 마감이 지난 공지는 추천 후보에서 제외합니다.

### 검색

- 제목/키워드 입력 즉시 필터링하는 UX를 기본으로 합니다.
- 서버 검색으로 변경할 경우 250~400ms 디바운스를 권장합니다.
- 검색 결과가 없으면 빈 상태를 보여줍니다.

### 필터

- 기본 선택은 전체입니다.
- 마감 임박은 별도 메뉴가 아니라 필터로만 제공합니다.
- 복수 선택 가능한 필터는 선택 상태를 칩 배경/테두리로 분명하게 표시합니다.
- 초기화는 전체 상태로 되돌립니다.

### 카드 인터랙션

- 카드 전체 클릭: 공지 상세로 이동 또는 상세 패널 오픈.
- 찜 버튼 클릭: 카드 이동을 발생시키지 않고 찜만 토글.
- hover: 카드가 1~2px 떠오르고 그림자가 조금 강해집니다.
- 찜 성공 시 즉시 아이콘 상태를 바꾸고 짧은 토스트를 노출합니다.
- 찜한 공지에 날짜가 있으면 내 캘린더에 연결합니다.

## 4. 신규 공지

- 원문 등록일 기준 최신순이 기본 정렬입니다.
- 검색과 출처 필터를 제공합니다.
- 필요하면 마감 임박/카테고리 필터를 함께 제공합니다.
- 추천도나 추천 이유는 필수 항목이 아닙니다.
- 카드 상세 이동과 찜 동작은 추천 공지와 동일합니다.

## 5. 공지 상세

필수 정보:

- 제목
- 출처
- 대상
- 신청 시작/마감
- 행사 시작/종료
- 활동 내용
- 혜택
- 추천 이유(추천 화면에서 진입한 경우)
- 원문 링크
- 찜 상태

표시 원칙:

- 날짜가 없으면 추정하지 않고 ‘일정 미정’으로 표시합니다.
- 상금은 있음/없음/미기재를 구분합니다.
- 마일리지는 제도별 점수와 조건을 분리하며 서로 다른 제도 점수를 합산하지 않습니다.
- 원문에 없는 혜택이나 금액을 추정하지 않습니다.

## 6. 찜

- 찜은 관심 표시이며 신청 완료 상태와 동일하지 않습니다.
- 학적/관심사를 수정해도 기존 찜은 유지합니다.
- 찜 토글은 낙관적 UI로 구현할 수 있으나 API 실패 시 원래 상태로 되돌리고 오류 토스트를 보여줍니다.
- 동일 공지에 중복 요청이 발생하지 않도록 요청 중 버튼 잠금을 권장합니다.

## 7. 내 캘린더

### 표시 항목

찜한 공지의 아래 일정을 표시합니다.

- 신청 시작
- 신청 마감
- 실제 행사 시작
- 실제 행사 종료

### 시각 구분

- 신청 일정과 실제 행사 일정은 라벨/배경색을 달리합니다.
- 일정 클릭 시 해당 공지 상세로 이동합니다.
- 여러 날짜에 걸친 일정은 시작~종료 범위를 이어진 일정으로 표현하거나, 구현 난이도에 따라 시작/종료 마커로 분리할 수 있습니다.
- 날짜가 전혀 없는 찜 공지는 우측 ‘일정 미정’ 영역에 표시합니다.

### 월 이동

- 이전/다음 월 버튼으로 월을 이동합니다.
- 월 변경 시 해당 월과 겹치는 일정을 다시 조회합니다.
- 연도 경계를 자연스럽게 처리합니다.

### 마감 이후

- 신청 마감이 지나 추천 목록에서 제외되더라도, 이미 찜한 공지의 예정된 실제 행사 일정은 캘린더에서 유지합니다.

## 8. 내 정보 수정

### 항목

- 학과
- 학년
- 학적 상태
- 관심 분야(복수)
- 활동 유형(복수)

### 저장

- 저장 성공: 수정 화면을 닫고 추천 결과를 새 정보 기준으로 갱신합니다.
- 저장 실패: 화면을 유지하고 오류 메시지를 표시하며 기존 서버 값은 보존합니다.
- 찜과 캘린더 데이터는 변경하지 않습니다.

### 취소

- 변경한 값을 서버에 반영하지 않습니다.
- 원래 저장된 값으로 되돌립니다.

## 9. 상태 화면

목록형 화면은 아래 상태를 모두 구현합니다.

### 로딩

- 첫 진입: 카드 스켈레톤 또는 중앙 로딩 상태.
- 추가 요청/필터 변경: 기존 목록을 유지한 채 로딩 인디케이터를 덧붙이는 방식을 우선합니다.

### 빈 상태

- 검색/필터 결과가 없을 때 “조건에 맞는 공지가 없습니다”와 필터 초기화 동작을 제공합니다.
- 찜 일정이 없을 때 캘린더에서 빈 상태를 명확히 안내합니다.

### 오류

- 네트워크/API 오류 메시지와 다시 시도 버튼을 제공합니다.
- 인증 만료는 별도 인증 처리 정책에 따라 로그인 화면으로 유도합니다.
- 저장 실패 시 입력값을 지우지 않습니다.

## 10. 접근성과 키보드

- 모든 버튼은 Tab으로 접근 가능해야 합니다.
- Enter/Space로 버튼과 찜 토글이 동작해야 합니다.
- 모달/상세 패널은 열렸을 때 포커스를 내부로 이동시키고 닫힐 때 원래 트리거로 복귀시키는 것을 권장합니다.
- Esc로 모달을 닫을 수 있도록 구현합니다.
- 색상만으로 상태를 전달하지 말고 텍스트/아이콘 라벨을 같이 사용합니다.

## 11. 애니메이션

- 카드 hover: 150~200ms.
- 모달/패널: opacity + translateY 150~220ms.
- 필터 선택: 배경/테두리 120~160ms.
- 로딩은 과도한 모션을 피하고 사용자 OS의 reduced-motion 설정을 존중합니다.

## 12. API 연결 시 주의

실제 API 경로와 필드는 `docs/api-contract.md`에서 프론트/백엔드가 합의한 뒤 확정합니다.

프론트에서 임의로 확정하면 안 되는 값:

- 추천 가중치
- 마감 임박 기준 일수
- 관심사 세부 목록
- AI 제공자
- 날짜/시간 포맷
- 페이지네이션 방식

## 13. 구현 우선순위

1. 공통 레이아웃/라우팅
2. 추천 공지 목록 + 상세 + 찜
3. 신규 공지 목록
4. 캘린더
5. 내 정보 수정
6. 로딩/빈/오류 상태
7. API 연동 및 통합 검수

## 14. 프로토타입 확인 방법

브라우저에서 `docs/design/pc/notice-prototype.html`을 직접 열면 클릭 가능한 프로토타입을 확인할 수 있습니다.

프로토타입에서 확인 가능한 동작:

- 좌측 메뉴 전환
- 검색
- 필터 선택/초기화
- 찜 토글
- 공지 상세
- 로딩/빈/오류 예시
- 캘린더 월 이동
- 일정 클릭
- 내 정보 수정 저장/취소/실패 예시

이 파일은 UI 동작 전달용이며 실제 데이터/API 구현은 포함하지 않습니다.
