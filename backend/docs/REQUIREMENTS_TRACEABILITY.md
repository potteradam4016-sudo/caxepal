# 저장소 기획 범위와 구현 대응

기준: 제공된 `caxepal-main.zip`의 `docs/product-scope.md`.
과거 상세 기획서와 현재 저장소가 다른 경우 현재 저장소의 확정 기능을 우선했습니다.
현재 저장소의 미정 사항은 구현 제안으로 남겨두었습니다.

| 요구 | 구현 | 주요 시험/제한 |
| --- | --- | --- |
| 비밀번호 변경 | 현재 비밀번호 확인·세션 전체 폐기 | 틀린 현재 비밀번호 거부·기존 세션 만료 시험 |
| 수동 학적 입력 | `api/profile.py` | 본인 범위·입력 검증; 학교 학적 원장 조회 없음 |
| 분야와 활동 구분 | `reference.py`, 프로필 온보딩 | 각각 하나 이상; 사전은 팀 제안값 |
| 추천 첫 화면용 데이터 | `/api/notices/recommended` | 개인화 API만 제공; 화면 미포함 |
| 최신성·마감 점수 제외 | `services/recommendations.py` | 날짜가 달라도 동일 score 시험 |
| 신청 마감 후보 제외 | `services/dates.py`, 추천 조회 | 날짜-only 끝 시각, 시각 마감, 미정 처리 |
| 신규 원문 등록일 정렬 | `/api/notices/new` | DB 삽입 순서와 무관한 정렬 시험 |
| 마감 독립 메뉴 없음 | 목록의 `closing_days`, D-Day | 별도 closing 메뉴/API를 만들지 않음 |
| 대상/활동/일정 3줄 | `AnalysisData.summary_lines` | 정확히 3개; 규칙 또는 AI 출처 구분 |
| 신청 일정과 실제 행사 구분 | `Schedule.kind` | 행사일이 신청 마감이 되지 않음 |
| 마일리지 제도 구분 | `mileages` 배열 | 자동인식 제도 제한·원문 근거·미합산 |
| 상금 있음/없음/미기재 | `Prize.status` | 미정·문의는 있음으로 바꾸지 않음 |
| 알려지지 않은 날짜 추정 금지 | 보수적 전체연도 파서·근거 확인 | 축약 날짜는 검수 대상 |
| 찜/취소 | `/api/bookmarks` | 사용자 A/B 격리·반복 요청 |
| 월간 캘린더 | `/api/calendar` | 월 경계·전체 기간 보존·부분 날짜·미정 |
| 마감 후 행사/찜 유지 | 달력은 마감 후보 필터와 분리 | 과거 신청+다음 달 행사 시험 |
| 프로필 수정 후 추천 변경 | 버전 증가·매 요청 재계산 | 관심 변경 후 추천 변경/찜 유지 |
| 세 출처만 수집 | 고정 URL 설정+허용 경로 | Glocal/외부 URL 거부 |
| 실제 공지 수집 | CMS 파서·HTTP 클라이언트·작업 큐 | 합성 입력 시험; 실적재·정확도는 현장 검수 필요 |
| 허가 완료 가정 금지 | 기본 수집 OFF | 원본 허가 문서 보존 |
| 프론트·공유 문서 충돌 방지 | backend-only 패키지 | 루트/프론트 변경 없음 |

## 제안 또는 아직 외부 확인이 필요한 항목

추천 가중치 35/25/15/10/15와 관심사 목록은 팀 합의 전입니다.
현재 opaque bearer 세션에는 refresh API가 없고 기본 유효기간은 24시간입니다.

자동 테스트에는 가상 계정·미래 날짜·합성 공지가 존재하지만 모두 임시 시험 DB에서만 사용합니다.
시작 스크립트나 migration은 그런 공지를 실제 DB에 심지 않습니다.

별도 공급자 계정 생성, GitHub push/PR 생성, 학교 서버/클라우드 배포, 프론트 코드 작성은 수행하지 않았습니다.

## 계정 계약

아이디·비밀번호 가입과 로그인은 `app/api/auth.py`, 입력 형식은 `app/schemas.py`, 저장은 `app/models.py`와 마이그레이션에서 처리합니다. 관리자 권한은 `grant-admin --username`으로 부여합니다.
