# 커밋과 PR 작성 안내

현재 규칙은 [루트 CONTRIBUTING](../../CONTRIBUTING.md)과 [PR 양식](../../.github/pull_request_template.md)을 따릅니다. 이 폴더의 `COMMIT_INITIAL.txt`, `COMMIT_UPDATE.txt`, `COMMIT_USERNAME_API.txt`는 초기 전달 당시 예시이며 현재 커밋에 자동 적용하지 않습니다.

## 변경분 확인

저장소 루트에서 `git status --short`, `git diff`, `git diff --cached`로 이번 변경과 이미 반영된 기능을 구분합니다. 파일을 선별해 stage하고 비밀값·DB·개인 데이터가 없는지 확인합니다. 제목에는 변경 목적, 본문에는 최종 구현과 실제 검증만 적습니다.

```text
docs: 현재 구현 기준 문서와 배포 점검 절차 정리

- 실제 화면·API·수집 정책에 맞춰 문서 갱신
- 운영 설정과 배포 전 확인 항목 정리
- 실행한 검증 결과와 미검증 환경 구분
```

위 제목은 문서 변경 예시입니다. 실제 테스트를 실행하지 않았다면 통과했다고 쓰지 않습니다.

## PR

일반 기능 PR의 base는 `dev`이고 최종 통합 PR만 `main`입니다. 관련 커밋 여러 개를 하나의 PR로 묶을 수 있으며 실제 변경 목적에 맞게 범위를 정합니다.

PR에는 변경 목적·내용, 실행 명령과 결과, 연결 이슈, 미확인 항목·검토 요청을 작성합니다. 화면 변경의 캡처는 저장소 PR 양식을 따릅니다. 테스트 환경과 운영 환경을 구분하고 현재 [검증 보고서](TEST_REPORT.md)를 참고합니다.
