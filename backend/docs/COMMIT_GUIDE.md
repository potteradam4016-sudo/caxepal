# 커밋 제목·본문과 PR 작성 안내

## 1. 어떤 커밋을 사용하나요?

백엔드를 아직 한 번도 커밋하지 않았다면 전체 파일을 초기 구현 커밋 하나로 묶을 수 있습니다.
첫 실행 수정본과 한국어 문서도 함께 포함합니다.

이미 이전 백엔드를 커밋했다면 과거 기능을 새로 추가했다고 쓰지 말고,
이번에 달라진 내용만 별도 수정 커밋으로 남깁니다. 공유 이력을 지우거나 강제로 덮어쓰지 않습니다.

| 현재 상태 | 사용할 제목 |
| --- | --- |
| 처음 백엔드를 올림 | `feat(backend): SCNU PICK 백엔드 초기 기능 구현` |
| 기존 백엔드를 갱신함 | `fix(backend): 실행 수정 통합 및 한국어 문서·검증 보강` |

수정본을 이미 별도로 올린 상태라면 본문에서 이미 반영된 수정 항목은 지우고 실제 차이만 남기세요.
앞으로 추가하는 기능은 로그인 수정·추천 정책 변경처럼 한 목적씩 작은 커밋으로 나누면 됩니다.

## 2. 처음 올릴 때의 커밋 본문

아래 파일에는 제목, 빈 줄, 본문까지 들어 있습니다.

[초기 구현 커밋 메시지](COMMIT_INITIAL.txt)

검증 문구는 이 통합본을 제작한 환경의 결과입니다.
사용자 PC에서 새로 확인한 결과가 있으면 환경과 실제 결과를 추가하세요.
Windows 확인 전에는 Windows 통과, 외부 연결 전에는 운영 완료라고 쓰지 않습니다.

## 3. 이미 커밋한 뒤 갱신할 때

[실행·문서 수정 커밋 메시지](COMMIT_UPDATE.txt)를 사용합니다.
팀원의 변경을 덮어썼거나 이전 코드와 이번 코드가 다른 경우에는 먼저 차이를 비교합니다.

## 4. 실제 커밋 명령

아래 명령은 **저장소 최상위**에서 실행합니다.
먼저 본인의 `feature/backend-*` 브랜치인지 확인합니다.
`dev`나 `main`에 직접 기능 커밋을 push하지 않습니다.

```powershell
git branch --show-current
git status --short
git add backend/
git diff --cached --name-only
git diff --cached
```

올라갈 목록에 `.env`, `.venv/`, `data/`, 실제 DB·메일·비밀키가 없는지 확인하세요.
`START.cmd`와 `.env.example`은 올려도 되지만 개인 `.env`는 제외합니다.

처음 올리는 경우:

```powershell
git commit -F backend/docs/COMMIT_INITIAL.txt
git push -u origin HEAD
```

이미 올린 코드를 갱신하는 경우:

```powershell
git commit -F backend/docs/COMMIT_UPDATE.txt
git push -u origin HEAD
```

`-F`는 파일 전체를 커밋 메시지로 읽는 옵션입니다. 두 커밋을 모두 실행하는 것이 아닙니다.
변경한 파일을 검토한 뒤 해당하는 명령 하나만 선택합니다.

## 5. dev에 합치기 위한 PR

GitHub에서 **base: `dev` / compare: 본인의 기능 브랜치**로 PR을 생성합니다.
사용자 PC에서 실행이 아직 확인되지 않았다면 초안 PR로 올려 그 사실을 적습니다.

처음 구현한 PR 제목:

```text
[백엔드] SCNU PICK 초기 API·DB·수집 기반 구현
```

기존 코드를 갱신하는 PR 제목:

```text
[백엔드] 실행 수정 통합·한국어 문서 정리·검증 보강
```

PR 본문 예시:

```markdown
## 변경 목적
프론트 담당자가 연결할 수 있도록 백엔드와 API 명세를 정리했습니다.

## 주요 내용
- 인증·프로필·공지·추천·찜·캘린더와 수집 작업 처리
- 첫 실행 수정 통합 및 한국어 실행·협업 문서
- 자동 테스트와 임시 서버의 실제 HTTP 검증

## 검증
- 제작 환경: Linux / Python 3.13.5 / SQLite
- 자동 테스트 106개 통과
- 실제 3104 포트 HTTP 요청 55회가 기대 결과와 일치
- 사용자 PC의 Windows 실행: 확인 후 결과 기입

## 남은 확인
- 실제 수집 허가 조건 반영과 원문 대조
- SMTP·AI·PostgreSQL·프론트 연동·배포
- 팀의 인증 방식·추천 정책·API 계약 검토

## 검토 요청
backend/docs/API_CONTRACT.md의 경로·요청·응답을 프론트 담당자와 확인해 주세요.
```

이 통합본을 제공한 것은 GitHub에 커밋·push·PR 생성까지 대신 수행했다는 뜻이 아닙니다.
팀 저장소에 반영하는 작업은 위 명령과 저장소 규칙에 따라 진행합니다.
