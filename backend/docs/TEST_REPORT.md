# 한국어 통합본 검증 보고서

검증 기준일: **2026년 9월 21일, 한국 시간**  
검증 대상: 이전 전체 백엔드 + 첫 실행 수정본 + 한국어 문서 + 추가 검증 도구를 합친 통합본  
검증 환경: **Linux x86_64 / Python 3.13.5 / SQLite 3.46.1**

## 1. 결론과 적용 범위

이 통합본은 제작 환경에서 자동 테스트 **106개가 통과**했습니다.
실제 `localhost:3104` 서버에 HTTP 요청 **55회**를 보내 기대한 성공·거부 응답을 확인했습니다.
새 DB 경로 생성, 마이그레이션 반복, 실행 실패 처리, 한국어 문서와 OpenAPI 일치도 확인했습니다.

**이 결과는 Windows 실행·온라인 패키지 설치·실제 외부 서비스·운영 배포까지 완료했다는 뜻이 아닙니다.**
기존에 설치된 패키지로 실행했으며, 설치 버전은 `verification-summary.json`에 있습니다.
인증·추천·수집 코드의 존재와 실제 SMTP·AI·학교 수집 성공을 구분합니다.

## 3. 자동 테스트의 주요 내용

인증에서는 이메일 확인 전 로그인 거부, 확인 토큰의 일회용·만료·목적 분리,
비밀번호 해시 저장, 비밀번호 재설정 후 기존 세션 폐기,
로그아웃·전체 로그아웃·탈퇴의 데이터 정리를 확인했습니다.

학적·추천에서는 본인 데이터 범위, 잘못된 관심사 저장 취소,
프로필 수정 버전 충돌, 실제 일치 점수와 이유,
마감·명확한 자격 불일치 제외, 시간 가산 부재를 확인했습니다.

찜·캘린더에서는 중복 찜 방지, 사용자 간 격리,
신청과 행사 분리, 월 경계, 일부 날짜만 있는 일정, 일정 미정,
신청 마감 후 향후 행사·기존 찜 보존을 확인했습니다.

수집·분석에서는 합성 HTML과 모의 HTTP 응답으로 선택자,
URL 제한, robots 규칙, 재시도 상한, 응답 크기 제한,
중복·변경 감지, 수집 실패 시 저장 자료 보존을 검사했습니다.
상금 미기재와 없음 구분, 제도별 마일리지, AI 실패·근거 검증도 모의 응답으로 시험했습니다.

**합성 HTML은 실제 학교에서 받은 페이지가 아니며, 모의 AI는 실제 모델 호출이 아닙니다.**

## 4. 실제 HTTP 55회 검증 흐름

`scripts/verify_backend.py`가 다음 과정을 임시 폴더에서 수행합니다.

```text
새 DB 준비·스키마 확인
→ 시험 전용 합성 공지 3건 입력
→ 실제 Uvicorn API와 작업 처리기 실행
→ 상태·Swagger·명세·공개 사전 조회
→ 사용자 2명 가입·개발 메일 확인·로그인
→ 학적·관심사 저장·충돌 검사·추천·검색·신규
→ 찜 중복·사용자 격리·신청/행사·월 경계·일정 미정
→ 관심사 변경·추천 재계산·찜 보존
→ 관리자 권한·수집 비활성화·CORS
→ 비밀번호 재설정·세션 폐기·로그아웃·탈퇴
→ 서버 종료·임시 DB·메일·계정·로그 삭제
```

55개 요청이 모두 200이라는 뜻은 아닙니다.
인증 누락의 401, 권한 부족의 403, 잘못된 입력의 422처럼 **예상한 거부도 정확한 결과**로 검사합니다.
수집 비활성화 검사는 실제 학교에 요청을 보내지 않습니다.
이메일 확인은 개발 `.eml` 파일을 사용하며 외부 이메일을 발송하지 않습니다.

## 5. 사용자 PC에서 반복하는 명령

`backend` 폴더에서 테스트 도구를 설치합니다.

```powershell
.\START.cmd --dev --setup-only
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe scripts/verify_backend.py
```

마지막 명령은 기본적으로 임시 포트를 사용합니다.
3104 포트 자체를 시험하려면 그 포트의 서버를 먼저 종료한 뒤 실행합니다.

```powershell
.\.venv\Scripts\python.exe scripts/verify_backend.py --port 3104
```

Linux에서는 `.venv/bin/python` 경로를 사용합니다.
제작 환경에서는 프로젝트와 관계없는 전역 pytest 플러그인 유입을 막기 위해 다음 명령을 사용했습니다.

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python -m pytest -o addopts= -q
```

온라인 설치가 가능한 새 가상환경에서는 보통 안내한 `python -m pytest`만 사용합니다.
Windows/Linux CI 예시는 `backend-ci.yml.example`에 있지만 원격 실행 결과는 아직 없습니다.

| 항목 | 상태와 이유 |

| 실제 PostgreSQL·권한·RLS·동시성 | 오프라인 SQL 생성만 확인 |
| Docker·학교 서버·클라우드 | 실제 배포 환경에서 미실행 |

| 대규모 부하·독립 보안 심사 | 기능 테스트와 별개의 검증 필요 |

사용자 PC의 실제 실행 오류는 현지 오류 로그를 확인해야 최종 판단할 수 있습니다.
