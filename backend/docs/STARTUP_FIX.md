# 첫 실행 수정과 통합 내역

이번 `backend` 전체 통합본에는 아래 수정이 **이미 반영되어 있습니다**.
이 문서는 추가로 적용해야 할 패치가 아니라 변경 이력입니다. 예전 수정 ZIP을 다시 덮어쓰지 마세요.

## 1. 이전 코드에서 수정한 문제

새 폴더에는 Git에서 제외한 `data/` 폴더가 없습니다.
SQLite 파일의 상위 폴더를 만들기 전에 DB 연결을 열던 순서를 수정했습니다.
다음 오류의 원인이 된 초기화 순서 문제이며, `migrations/env.py`에서 연결 전에 폴더를 만듭니다.

```text
sqlite3.OperationalError: unable to open database file
```

설정 검사에서 오류 내용을 캡처한 뒤 표시하지 않던 문제도 수정했습니다.
이제 잘못된 설정 항목은 표시하되, 비밀번호·비밀키를 포함할 수 있는 입력값 전체는 출력하지 않습니다.

API 또는 수집 작업 처리기가 비정상 종료되면 실행기도 실패 코드로 종료합니다.
다른 자식 프로세스는 정리하며, Windows 시작 파일은 실패 시 오류 창을 유지합니다.
기존 `.env`를 자동으로 덮어쓰거나 기존 DB를 삭제하지 않습니다.

## 2. 이번 한국어 통합 검수에서 반영한 내용

| 대상 | 반영 내용 |
| --- | --- |
| 전체 Markdown 문서 | 제목과 설명을 한국어로 정리하고 실행 방법·보고서를 현재 코드와 통일 |
| `README.md` | 전체 통합본 안내, 문서 읽는 순서, 반복 가능한 검증 명령 |
| `start.py` | 단계별 진행·설정 오류·종료 안내를 한국어로 표시 |
| API 설명 | Swagger에 표시되는 모든 작업의 요약을 한국어로 지정 |
| `docs/openapi.json` | 수정한 코드에서 다시 생성 |
| `tests/test_documentation.py` | 한국어 제목·문서 링크·OpenAPI 일치·안전한 예제 설정 검사 |
| `scripts/verify_backend.py` | 실제 HTTP로 주요 기능을 검증하는 임시 환경 도구 |
| `tests/test_runtime_smoke.py` | 위 실제 HTTP 검증을 자동 테스트에 포함 |
| `tests/conftest.py` | 개인·운영 환경변수가 테스트 설정에 섞이지 않도록 격리 |
| `docs/COMMIT_GUIDE.md` | 초기 업로드와 기존 커밋 이후 갱신을 구분한 커밋·PR 예시 |

기능 경로·JSON 필드명·DB 스키마·인증 방식·추천 배점은 변경하지 않았습니다.
프론트엔드나 실제 학교 공지 데이터를 추가하지 않았습니다.
파일명과 프로그래밍 식별자는 기존 코드와 연결되므로 유지합니다.

`START.cmd`는 Python이 설치되지 않은 상황에서도 오류를 보여줘야 하므로 짧은 초기 안내를 ASCII로 유지합니다.
Python 실행 이후 안내와 Markdown 문서는 한국어입니다. 외부 패키지의 설치·오류 출력 언어는 해당 도구에 따릅니다.

## 3. 사용자 PC에서 확인하기

PowerShell의 현재 위치가 `backend`일 때 실행합니다.

```powershell
.\START.cmd
```

브라우저에서 `http://localhost:3104/health`를 열어 아래 응답을 확인합니다.

```json
{"status":"ok","database":"ok","frontend_included":false}
```

`http://localhost:3104/docs`는 API 시험 화면입니다. 별도 프론트 웹 화면은 포함하지 않았습니다.
주소를 출력했다는 사실만으로 실행 성공이라고 판단하지 않습니다.

자동 테스트 준비·실행:

```powershell
.\START.cmd --dev --setup-only
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe scripts/verify_backend.py
```

기존 서버가 3104를 사용한다면 종료한 뒤 다시 실행하세요.
Python 버전·패키지 다운로드·프록시·잘못된 개인 설정·사용 중인 포트는 사용자 환경에서 따로 확인해야 합니다.

## 4. 검증 결과 해석

이번 통합본의 최신 수치와 실제 시험 범위는 [검증 보고서](TEST_REPORT.md)가 기준입니다.
과거 원본의 테스트 수치와 수정 ZIP의 수치를 현재 결과처럼 혼용하지 않습니다.

Linux에서 통과한 결과를 Windows의 실제 `.cmd` 실행 성공이라고 표현하지 않습니다.
현재 통합 검증은 기존에 설치된 패키지를 사용했습니다.

사용자 PC의 오류 로그를 받지 않았으므로 사용자 PC의 모든 실행 문제가 해결되었다고 단정하지 않습니다.
오류를 공유할 때는 비밀번호·토큰·DB 접속 문자열을 가리고 `.env` 전체는 보내지 마세요.
